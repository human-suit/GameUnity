# Работа вдвоём — Unstable Experiment (Game Jam)

> Репо: https://github.com/human-suit/GameUnity  
> Unity: **`Unity/UnstableExperiment/`**  
> Версия Unity: **2022.3.20f1** (у обоих одинаковая!)

---

## Главное правило

**Не работайте одновременно над одним файлом** — особенно над `Main.unity` и одним prefab.

```
main     ← только стабильная игра (merge сюда)
 ↑
dev1     ← твоя ветка
dev2     ← ветка напарника
```

**В main напрямую не коммитим.** Только через merge из своей ветки.

---

## 0. Настройки Unity (уже в проекте)

В **Project Settings → Editor** должно быть:

| Настройка | Значение |
|-----------|----------|
| Version Control | **Visible Meta Files** |
| Asset Serialization | **Force Text** |

Это уже в `ProjectSettings/EditorSettings.asset`.  
Без этого Git плохо мержит сцены и prefab'ы.

---

## 1. Первый запуск (новый компьютер)

```bash
git clone https://github.com/human-suit/GameUnity.git
cd GameUnity
```

1. Unity Hub → Open → `GameUnity/Unity/UnstableExperiment`
2. Дождись импорта (Unity создаст `Library/` — её нет в Git, это нормально)
3. Выбери **свою ветку**:

```bash
# Dev 1
git checkout dev1
git pull origin dev1

# Dev 2
git checkout dev2
git pull origin dev2
```

4. Открой `Assets/Scenes/Main.unity`
5. **Unstable Experiment → Шаг 1** → **Шаг 2** → Play ▶

---

## 2. Ветки dev1 / dev2

### Один раз при старте джема

```bash
git checkout main
git pull origin main
git checkout -b dev1
git push -u origin dev1

# второй разработчик:
git checkout main
git checkout -b dev2
git push -u origin dev2
```

### Каждый рабочий день

**Dev 1:**
```bash
git checkout dev1
git pull origin dev1          # забрать свои + то что влили в main
# ... работа в Unity ...
git add Unity/UnstableExperiment/
git commit -m "Add enemy aggro radius"
git push origin dev1
```

**Dev 2:**
```bash
git checkout dev2
git pull origin dev2
# ... работа ...
git commit -m "Add walk animation frames"
git push origin dev2
```

### Слить в main (1–2 раза в день)

На GitHub: **Pull Request** `dev1 → main` или `dev2 → main`  
Или в чате: «мержу dev1 в main» → один человек мержит, второй делает:

```bash
git checkout dev2
git pull origin main          # подтянуть изменения после merge
```

## 3. Кто что делает (наша игра)

Не «оба пишут код в одном месте», а **разные системы и папки**.

### Dev 1 — Overworld + Combat (логика)

| Зона | Папка | Примеры |
|------|-------|---------|
| Мир | `Scripts/Overworld/` | ходьба, двери, комнаты, туман |
| Бой | `Scripts/Combat/` | lottery, билеты, HP, ход врага |
| Тест | `Scenes/Test/OverworldTest.unity` | проверка WASD без UI |
| Тест | `Scenes/Test/CombatTest.unity` | проверка боя без карты |

### Dev 2 — Art + UI (картинка и интерфейс)

| Зона | Папка | Примеры |
|------|-------|---------|
| Арт | `Resources/Art/` | персонаж, комнаты, враги (PNG!) |
| UI | `Scripts/UI/` | HUD, Route Map, экран боя |
| Prefab | `Prefabs/` | Player, Enemy, CardChit |
| Тест | `Scenes/Test/UITest.unity` | проверка UI отдельно |

### Оба НЕ трогают без договорённости

- `Scenes/Main.unity` — **только один** интегрирует, по очереди
- Чужой prefab — напиши в чат: «меняю Player.prefab»

## 4. Структура папок

```
Assets/
├── Scenes/
│   ├── Main.unity              ← финальная игра (осторожно!)
│   └── Test/
│       ├── OverworldTest.unity ← Dev1
│       ├── CombatTest.unity    ← Dev1
│       └── UITest.unity        ← Dev2
├── Scripts/
│   ├── Overworld/              ← Dev1: PlayerMove, VisionFog…
│   ├── Combat/                 ← Dev1: lottery, damage…
│   └── UI/                     ← Dev2: HUD, RouteMap…
├── Prefabs/
│   ├── Player/
│   └── Enemies/
├── Resources/
│   ├── Art/                    ← Dev2: все спрайты
│   └── Data/                   ← JSON (rooms, tickets)
└── Docs/
    ├── ШАГИ.md                 ← как собрать сцену
    └── РАБОТА-В-ДВОЁМ.md       ← этот файл
```

**Работайте в Test-сценах**, потом один переносит в Main.

## 5. Что в Git, что нет

### ✅ Коммитим

```
Assets/
ProjectSettings/
Packages/manifest.json
*.meta          ← рядом с каждым ассетом!
```

### ❌ НЕ коммитим

```
Library/
Temp/
Logs/
Obj/
Build/
Builds/
UserSettings/
*.csproj / *.sln
```

Если друг клонирует репо — Unity сам восстановит проект из `Assets/` + `ProjectSettings/`.

## 7. Конфликты — если случились

### Обычные файлы (.cs)

Git покажет конфликт → открой файл → убери `<<<<<<` → save → commit.

### Сцена (.unity) или prefab

**Не мержите вслепую.** Проще:

1. Напиши напарнику
2. Один откатывает свои правки в сцене
3. Второй пушит
4. Первый заново добавляет своё

**Профилактика:** разные Test-сцены, Main — по очереди.
